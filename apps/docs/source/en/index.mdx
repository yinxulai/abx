# What abx is

abx (airlock box) is a **macOS tray app**. Drop a folder or file onto the tray, pick an agent, and abx starts a **throwaway isolation cell** running Claude Code, Codex or dsh. The agent can read code, run tests and write files as if it were on your machine — but it **cannot reach your real credentials** and **cannot leave the allowlist**.

It solves one concrete dilemma:

| Today's choice | Consequence |
|---|---|
| Hand the agent an API key | It can do the whole job — and also read `~/.ssh`, `curl` your production database, or `rm -rf` |
| Give it neither credentials nor folders | It is safe and useless |

abx bets that this is a false choice. Credentials stay outside and are injected by the airlock; only the task folder is mounted; egress is limited to an allowlist. The agent still gets work done, but everything it receives is **borrowed, gated and logged**.

## What one task looks like

```text
You drop repo/ onto the tray
        │
        ▼
  A throwaway cell: repo/ writable, shared area read-only, config read-only
        │
        ▼
  agent in cell ──request──▶ airlock (host) ──▶ OSW (host) ──▶ real provider
        │                        │
        │                        └─ validates cell token, egress allowlist,
        │                           replaces the placeholder, writes the audit
        └─ only gets one baseUrl + one placeholder
```

Models and keys are configured in **OSW** on the host — it already funnels all your channels into one local address. abx copies no provider configuration and brings no key into the cell. The airlock is the cell's front door; OSW is the dispatcher behind it.

## What it is not

- **Not another model manager.** Providers, models, routing and failover live in OSW; abx owns the cell, the gates and the record.
- **Not a virtual machine.** Cells share the host kernel; abx makes no promise about kernel-level escapes.
- **Not a network anonymiser.** Outbound traffic still uses your own IP.
- **Not a guard against secrets you hand over yourself.** Drop a `.env` into the shared area and the agent can read it.
- **Not cross-platform** (V1 is macOS only) and has no command-line form.
