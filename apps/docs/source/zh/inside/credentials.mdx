# 凭据不出舱

这是整个产品的一句话解释：**舱里压根不存在一把可以泄漏的真密钥。**

不是「我们把密钥藏得很深」——藏起来的东西会被找到；**不存在的东西不会**。

## 舱内 agent 看到的全部

舱里的 agent 只会看到一个自定义供应商、一个 baseUrl、一个**无条件会被替换掉的占位符**：

```text
provider : custom
baseUrl  : http://<气闸舱面>/u/osw
apiKey   : abx-placeholder-anthropic   # 假值，不是任何供应商的密钥
```

没有供应商列表、没有模型清单、没有账户、没有第二把密钥。那个 `apiKey` 就算被 agent 打印出来、
写进 commit、发给别人，也没有任何用：气闸转发时不看它，直接换成真密钥（或者在没有真密钥的上游上把它剥掉）。

<Callout title="两种投递方式" type="note">
Claude Code 支持自定义请求头，舱令牌走 `X-Abx-Cell` **请求头**，不出现在 URL 里；
Codex 与 dsh 没有这个手段，才退回 `/c/<舱令牌>/...` 的**路径前缀**。路径前缀会让令牌出现在
agent 自己的日志里——那仍然是我们自己签发的一次性令牌，不是真凭据。
</Callout>

## 谁拿着什么

| 谁 | 拿什么 |
|---|---|
| **OSW**（宿主） | 供应商、密钥、模型路由、故障转移 |
| **abx 气闸**（宿主） | 舱令牌校验、出口白名单、占位符替换、审计 |
| **舱内 agent** | **一个 baseUrl，一个占位符。别的什么都没有** |

模型和密钥都配置在 OSW。abx **不复制任何供应商配置**：上游、密钥、模型名都不进舱，
舱里也不允许出现 `model` 字段——换模型是 OSW 的事，abx 不参与。

## 真密钥在哪

- 配置里只写**环境变量名**（`secretEnv`）或**文件路径**（`secretFile`），不写密钥值。
  加载时如果发现长得像明文密钥的值，会直接拒绝启动。
- 密钥只在气闸进程内存里展开，转发请求的那一刻才写进请求头。审计里只记「注入了没有」，
  **永远不记值本身**。
- 上游不需要鉴权时（例如本机的 OSW），气闸做的是**剥掉**舱内带来的占位符，而不是注入。

## 宿主的环境变量也不会跟着进去

启动舱之前，abx 会把宿主环境剃一遍，再只放入气闸地址和占位符。默认不进舱的包括：

- ssh-agent、GPG 代理、`GIT_ASKPASS` —— 有了它们，舱内能以你的身份用你的私钥；
- `DOCKER_HOST` / `DOCKER_CONFIG` / `KUBECONFIG`、云凭据文件路径；
- 名字像凭据的变量：`*_API_KEY`、`*_TOKEN`、`*_SECRET`、`*_PASSWORD`、`*_CREDENTIALS` 等。

## 凭据文件与配置是「同目录邻居」

每个 agent 的登录凭据就躺在配置文件旁边：

```text
~/.claude/settings.json        配置
~/.claude/.credentials.json    ⚠️ 账户 OAuth 凭据
~/.codex/config.toml           配置
~/.codex/auth.json             ⚠️ 登录凭据
```

所以 abx **绝不挂载整个配置目录**，只挂自己生成的那一个文件；挂载时凭据文件名一律拒绝
（`.credentials.json`、`auth.json`、`*.env`、`*.pem`、`id_rsa*`）。

## 它挡不住什么

- 你**主动**把 `.env`、密钥文件拖进共享区或任务目录，agent 就能读到。abx 不替你做这个判断。
- agent 自己产出的内容里可能带着你给它的东西（例如代码里的测试密钥）。
- 容器共用宿主内核，abx 不承诺防住内核级逃逸。
