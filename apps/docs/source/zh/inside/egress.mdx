# 出口默认拒绝，且留痕

舱内 agent 的每一次出网都要经过气闸。规则只有一条：**白名单里没有的域名，一律拒绝。**

默认配置里白名单是空的，空名单的语义是**全部拒绝**，不是全部放行。这条默认值本身就是一道防线：
一个默认全开、等你手动收紧的沙箱，在真实使用里等于没有沙箱。

## 白名单怎么写

```json
{
  "egress": {
    "allow": [
      { "pattern": "api.anthropic.com", "upstreamId": "anthropic" },
      { "pattern": "*.openai.com", "upstreamId": "openai" },
      "registry.npmjs.org"
    ]
  }
}
```

三种写法：

| 写法 | 匹配 | 注意 |
|---|---|---|
| `api.example.com` | 只匹配它自己 | 精确 |
| `*.example.com` | 只匹配子域 | **不**匹配 `example.com` 本身，也不跨多级 |
| `.example.com` | 它自己 + 全部子域 | 想同时放行主域和子域时用它 |

**不支持裸 `*`。** 写了它想要的是「全部放行」，那和白名单这个机制本身冲突；真需要放行很多域名，
应该逐条看见它们。IP 字面量（例如 `127.0.0.1`）也是合法的条目。

一条规则可以只写域名（直通：剥掉占位符后原样转发），也可以绑定一个上游（转发时注入该上游的真凭据）。
绑定上游**不能绕过白名单**：`/u/<上游>/...` 这条路由同样要先过一遍域名检查。

## 一次请求的路径

```text
舱内 agent
  │  baseUrl + 占位符
  ▼
气闸舱面 ── 校验舱令牌 ──▶ 解析目标域名 ──▶ 在白名单里？
                                              │ 否 → 403 + 审计（拒绝原因：出口）
                                              │ 是 → 注入/剥离鉴权头 → 转发
                                              ▼
                                            上游（生产形态：本机 OSW）
```

每一步拒绝都有明确原因：令牌不对、路由不认识、上游不存在、白名单未命中、凭据取不到。
它们各自对应一个状态码，并且都会写进审计。

## 审计

每一次出网追加一行 JSONL，只追加、不提供修改接口。默认位置是配置里的
`broker.auditPath`（`./abx-audit.jsonl`），文件权限 `0600`。一条记录回答：

| 问题 | 记什么 |
|---|---|
| 什么时候 | 带毫秒的时间 |
| 哪个会话 | 舱的身份（不是你的身份） |
| 去了哪 | 方法、目标域名、路径 |
| 放没放行 | 放行，或拒绝原因 |
| 结果如何 | 状态码、耗时 |
| 密钥动过没有 | **只有「注入了 / 没注入」这个布尔值** |

<Callout title="审计里没有密钥值" type="note">
记录是逐字段白名单序列化的，`Authorization` 的值根本不在可写字段里。请求路径这类外部输入
也会被压成一行并截断，避免有人用换行在日志里伪造一条记录。
</Callout>

被拒绝的域名同样留痕，这是有意的：白名单太紧时，你要能看见「它想连哪个域名」，
然后一条一条加，而不是靠猜。

<Callout title="一个已知缺口" type="warning">
审计写入失败时，当前实现只把错误打到 stderr，**不会阻断这次请求**。
也就是说，「每一次出网都留痕」成立的前提是审计文件写得进去。这一条列在[明确不做的边界](/limits/limitations)里。
</Callout>

## 为什么生产形态只需要放行一个域名

生产形态下，气闸的唯一下游是宿主上的 OSW（`127.0.0.1:9300`）。舱内 agent 不需要直连任何供应商，
所以白名单里通常只需要本机地址。真实 agent 还会连什么（例如包管理器、遥测），
只能靠实测一条条补 —— 默认拒绝会让缺口**立刻暴露**，而不是悄悄放行。
