# 历史留在哪里

舱是**一次性**的：agent 退出，容器销毁。这是隔离的一部分 —— 写在启动项、cron、shell 配置里的东西
留不下来，下一次起舱也不会带着上一次的残留。

但「一次性」不等于「什么都留不下」。哪些东西活过舱，取决于它放在哪。

## 活得过舱的东西

| 放在哪 | 在舱内是什么 | 舱销毁后 |
|---|---|---|
| **任务目录** | 可写挂载，通常是 `/workspace` | ✅ 它就是宿主上的那个目录，改动原样留下 |
| **共享区** | 只读挂载 | ✅ 原件在你自己的磁盘上，移除条目也只解除共享，不删文件 |
| **取回区** | 每一舱一个可写目录 | ✅ 产物落在宿主，舱退出也还在 |
| **审计文件** | 宿主写，舱内看不见 | ✅ 只追加，不随舱清理 |

所以「把结果带回来」的正确做法是写进任务目录或取回区，而不是留在 agent 的对话历史里。

## 不会活过舱的东西

- **容器里的临时文件**：`/tmp` 是 tmpfs，舱一退就没了。
- **abx 生成的配置**：每次起舱重新生成，只读，不保留改动。
- **agent 自己的会话历史**：例如 `~/.claude` 下的对话记录、`~/.codex` 的本地状态。
  它们落在容器的可写层里，容器销毁就一起没了。

## 设计中的「按实例持久化目录」

一次性舱有一个真实的代价：agent 第二次进来不记得第一次聊过什么。

设计上的解法是给每个 agent 登记一组**历史目录**（例如 `~/.claude`），abx 把它们挂到宿主上
**按实例持久化**的目录：

```text
宿主：~/.abx/…/<某一实例>/history/…
   │  只挂 agent 自己写历史的那几个目录
   ▼
舱内：~/.claude/…（路径与 agent 期望的一致）
```

这样历史能跨舱保留，而**登录凭据仍然不在舱里** —— 挂的是历史目录，不是整个 home，
凭据文件名照旧在黑名单上。哪些目录算历史，必须写在 agent 清单里，因为它是**某个 agent 的性质**，
会随 agent 版本漂移；写在渲染器或挂载策略里，没人会记得跟着 agent 升级一起改。

<Callout title="这一项还在落地" type="warning">
agent 清单里目前**还没有**登记历史目录（清单的 `statePaths` 字段仍在设计中），
所以现在起舱**不会**挂任何持久化目录：agent 自己的会话历史随舱销毁。
任务目录、共享区、取回区与审计不受影响，仍然按上面的表工作。
</Callout>

## 为什么宁可先丢历史

反过来（为了保留历史，把整个 home 挂进舱）会把 `~/.ssh`、云凭据、浏览器数据一起送进去，
把「凭据不出舱」这条最重要的承诺直接作废。历史可以重读、重问、重新生成；
泄漏的密钥不能。

在持久化目录落地之前，想保留上下文，就把上下文写进**任务目录**：笔记、决策、进度都放那里，
下一次起舱时 agent 读得到。
