# 历史留在哪里

舱是**一次性**的：agent 退出，容器销毁。这是隔离的一部分 —— 写在启动项、cron、shell 配置里的东西
留不下来，下一次起舱也不会带着上一次的残留。

但「一次性」不等于「什么都留不下」。哪些东西活过舱，取决于它放在哪。

## 活得过舱的东西

| 放在哪 | 在舱内是什么 | 舱销毁后 |
|---|---|---|
| **任务目录** | 可写挂载，通常是 `/workspace` | ✅ 它就是宿主上的那个目录，改动原样留下 |
| **共享区** | 只读挂载 | ✅ 原件在你自己的磁盘上，移除条目也只解除共享，不删文件 |
| **取回区** | 每一舱一个可写目录 | ✅ 产物落在宿主，舱退出也还在 |
| **审计文件** | 宿主写，舱内看不见 | ✅ 只追加，不随舱清理 |
| **agent 的会话历史** | 按实例持久化的可写目录（清单里的 `statePaths`） | ✅ 留在宿主，下一次同一个实例接着用 |

## 不会活过舱的东西

- **容器里的临时文件**：`/tmp` 是 tmpfs，舱一退就没了。
- **abx 生成的配置**：每次起舱重新生成，只读挂载，手改留不下来。
- **可写层里的其他文件**：历史目录之外，agent 在容器里写的东西都随容器销毁。

## 按实例持久化目录

一次性舱有一个真实的代价：agent 第二次进来不记得第一次聊过什么。解法是给每个 agent 在清单里
登记**历史目录**（`statePaths`，目前的形态是 `~/.claude` / `~/.codex` / `~/.dsh` 这一格，
挂载权限 `rw`），abx 按**实例**把它挂到宿主上：

```text
宿主：~/.abx/instances/<实例>/            （ABX_INSTANCES_ROOT 可覆盖）
  ├─ sessions.jsonl                        abx 自己的记账，只写宿主，舱内看不见
  └─ <agent id>/                           ← 整个目录以 rw 挂进舱
       ├─ …                               agent 自己写的历史
       └─ settings.json                    abx 每次起舱现写，以 ro 嵌在上一行里
舱内：<舱内 home>/.claude                  （默认 /home/node/.claude）
```

- **实例默认就是 agent**：「再开一次 claude」接的是上一次那份历史。`--instance <id>`
  可以开一份平行历史，与默认那份互不影响。
- **实例目录不是你的 `~/.claude`**：它由 abx 创建、初始为空。挂的是历史目录，不是整个 home，
  所以你的登录凭据、`~/.ssh`、其他工具的数据都不会进舱。
- **整目录挂，不列子路径**：agent 的 home 结构是它自己的实现细节，会随版本漂移；
  列一张子路径白名单，漏掉一个的后果是那部分历史**静默消失**。
- **配置只读覆盖**：abx 生成的 `settings.json` 在同一个位置再以 `ro` 盖一层，agent 读得到、
  改不动；同目录里的其他文件照常可写。

挂载源在起舱之前要过几道闸（形状、软链不逃逸、不落在宿主 home、不碰凭据目录），
`ABX_INSTANCES_ROOT` 也不能指到别处去。配错了会在按下回车之前就报错，而不是挂上一个
看起来正常、实际写着别处数据的目录。

<Callout title="实例目录会长期留在宿主上" type="warning">
历史不再随舱销毁，所以它会一直占着磁盘，也可能包含你不想长期保留的对话内容。
当前还没有「删除某个实例」的命令；要清掉某一份历史，只能在宿主上手动删
`~/.abx/instances/<实例>/`。删之前确认那个实例不需要了——这个动作不可撤销。
</Callout>

## 为什么宁可这样也不挂整个 home

为了保留历史而把整个 home 挂进舱，会把 `~/.ssh`、云凭据、浏览器数据一起送进去，
把「凭据不出舱」这条最重要的承诺直接作废。历史可以重读、重问、重新生成；
泄漏的密钥不能。所以挂载单位是**清单登记的那一个历史目录**，不是 home。
