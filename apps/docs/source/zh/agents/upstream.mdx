# 唯一的生产上游：OSW

abx 不管理模型，也不保存供应商密钥。**生产形态下，气闸的唯一下游是宿主上的 OSW。**

OSW 已经把你手上的渠道收进一个本地地址；abx 在它前面加一道舱门：

```text
舱内 agent
  │  baseUrl = http://<气闸舱面>/u/osw + 占位符
  ▼
abx 气闸（宿主）
  │  校验舱令牌 → 出口白名单 → 剥掉占位符 → 记审计
  ▼
OSW（宿主，127.0.0.1:9300）        ← 供应商、密钥、模型路由、故障转移都在这
  ▼
真实供应商 API
```

三层各管一件事，**没有一层需要知道下一层的密钥**。

## 为什么不需要改 OSW

OSW 的代理面**没有鉴权**，这是设计而不是缺陷：它只监听回环地址，局域网与本机其他用户都够不到它。

| 谁 | 能不能碰到 OSW | 为什么 |
|---|---|---|
| 舱内 agent（容器） | ❌ | 容器只能经宿主对外的接口访问宿主；`127.0.0.1` 不在其中 |
| abx 气闸（宿主进程） | ✅ | 它就在宿主上，直连 `127.0.0.1:9300` |

于是气闸天然成为**舱内唯一的出口**，OSW 继续只做它自己那件事。不需要给 OSW 加鉴权、加监听面，
也不需要舱身份头。

<Callout title="目标接线" type="note">
气闸侧的上游只有一条：

```text
id      : osw
baseUrl : http://127.0.0.1:9300
凭据    : 无 —— OSW 不校验；气闸把舱内带来的占位符剥掉再转发
```

出口白名单同样要对它生效，所以 `127.0.0.1` 必须出现在白名单里
（`/u/osw/...` 也会先过一遍域名检查）。开发实例的端口是 `19300`。
</Callout>

## 接入仍在落地

生产形态「唯一下游是 OSW」是目标状态，**接入本身还没完成**：现在仓库里的示例配置仍然保留
三个直连上游（`anthropic` / `openai` / `dsh`）作为开发期与自测能力。它们不是生产形态，
正式使用时应收敛成只有 `osw` 一个上游。当前进度的唯一来源是仓库内的路线图，
不在这份使用手册里重复。

## 换模型、加渠道都在 OSW 做

- **加一个供应商**、**换一个模型**、**配故障转移**：都在 OSW 里完成，abx 不需要重启，也不需要改配置。
- **abx 不写 `model` 字段**：舱内 agent 的请求原样交给 OSW，由 OSW 决定落到哪个模型。
- **abx 不复制供应商列表**：舱里没有第二份地址、第二把密钥、第二个账户。

这也是安全叙事的一部分：舱内 agent 就算把自己看到的配置全部打印出来，也只有一扇门和一个假 token。

## OSW 没跑起来会怎样

气闸转发时连不上 `127.0.0.1:9300`，这条请求会以「上游错误 / 超时」结束，并写进审计。
舱内 agent 会看到一次失败的请求，而不是一个静默的空响应。

排查顺序见[常见故障](/limits/troubleshooting)。
