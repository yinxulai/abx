# 常见故障

排查的第一现场是**审计流水**：每一次出网都有一行记录，被拒绝的也在里面。
默认位置是 `broker.auditPath`，也就是 `./abx-audit.jsonl`。

## 面板不出来

| 现象 | 先看 | 处理 |
|---|---|---|
| 菜单栏没有图标 | 应用是否在运行 | 启动 abx；Dock 里**没有**图标是正常的 |
| 点图标没反应 | 是否点在了别的菜单栏图标上 | 再点一次；面板失焦会隐藏而不是关闭 |
| 开发模式起不来 | 是否有图形会话 | 托盘与拖放需要真实的 macOS 图形环境，纯终端 / 无 `DISPLAY` 的机器跑不了 |

## 请求被 403：域名不在白名单

审计里这一行会写「拒绝」，原因是出口白名单未命中。处理方式是**加一条规则**，不是关掉白名单：

- 精确域名：`api.example.com`
- 只含子域：`*.example.com`（**不**匹配 `example.com` 本身）
- 自身加子域：`.example.com`
- IP 字面量也可以，例如 `127.0.0.1`

先看审计里「它到底想连哪个域名」，再一条一条加。真实 agent 还会连包管理器、遥测之类的域名，
第一次跑几乎一定会遇到几条拒绝记录 —— 这是默认拒绝在正常工作，不是故障。

## 请求被 401：舱的身份不对

- 舱令牌是**一次性的**：舱销毁后就失效。拿旧 URL / 旧令牌再请求，会得到 401。
- 舱内自报的会话 id 不参与鉴权；伪造它不会放行，只会让审计里的归属难看。
- 不要手动改生成配置里的 baseUrl；每次起舱都会重新生成。

## 502：上游凭据取不到

审计里的拒绝原因是凭据缺失。检查：

- 配置里写的 `secretEnv` 环境变量，在**启动 abx 的那个环境**里是否存在；
- 或者 `secretFile` 指向的文件是否可读；
- 配置里有没有误写成明文密钥 —— 加载时会直接拒绝启动。

OSW 不需要凭据，所以生产形态下这条通常不是「缺 Key」，而是「OSW 没起来」。

## 502 / 504：上游错误或超时

- OSW 是否在运行、端口是否对；
- OSW 那边的供应商是否可用（故障转移由 OSW 负责，abx 不重试）；
- 单次转发超时默认 120 秒，可以在 `broker.requestTimeoutMs` 调整。

## Docker 相关

| 报错 / 现象 | 原因 | 处理 |
|---|---|---|
| 起不了舱、提示连不上 Docker | Docker Desktop 没启动 | 启动 Docker Desktop，等它完全就绪 |
| `mounts denied` | 任务目录或共享区不在 Docker Desktop 的共享路径里 | 把目录移到 home 下，或在 Docker Desktop 里添加共享路径 |
| 舱内连不上气闸 | 用了 `172.17.0.1` | Docker Desktop 上这个地址不可用；改走 `host.docker.internal` 与来源网段校验 |

## agent 找不到命令 / 不读配置

- **镜像尚未构建**：<code>{AGENTS_IMAGE_UNBUILT.join(' / ')}</code> 在清单里登记了镜像，
  但镜像还没建（版本写的是 `unbuilt`），起舱时 Docker 会报找不到镜像。先把对应镜像构建出来
  （见 [claude / codex / dsh](/agents/available) 的「镜像」一节）。
- **覆盖成了裸镜像**：`session.image` 是给裸容器验证留的出口；写成只装了 node 的镜像后，
  里面没有 claude / codex / dsh，舱内会报命令不存在。跑 agent 时不要写 `session.image`，
  让它落到该 agent 自己的镜像上。
- **配置落点不对**：agent 只会去它期望的路径找配置；abx 生成的路径与宿主约定一致，别手动改。
- **dsh 尚未核实**：命令名与配置字段名都缺少权威来源，出错时先按它的文档核对一遍。

## local 后端

如果你在配置里把后端切成了 `local`，启动时会看到一条警告：**它不是沙箱**，命令以当前用户身份
直接在宿主上执行，没有文件系统隔离、没有资源限额、没有网络隔离。它只用于在 Docker 不可用时
验证会话编排的逻辑，**禁止用于演示**。切回 `docker` 才有隔离。
