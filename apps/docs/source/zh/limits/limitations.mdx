# 明确不做的边界

先把边界说清楚，免得把「不想做」当成「没做完」，也免得把「还没验过」当成「已经能用」。

## 安全上明确不承诺

- **不承诺防住内核级逃逸**。舱是容器，共用宿主内核，不是虚拟机。
- **不承诺防住你主动递进去的秘密**。你把 `.env`、私钥拖进共享区或任务目录，agent 就能读到。
- **不承诺网络侧匿名**。出网 IP 仍然是你自己的。
- **不承诺审计一定落盘**。审计写入失败时，当前实现只报错、不阻断请求；「每次出网都留痕」
  成立的前提是文件写得进去。
- **舱面的来源校验还没装上**。气闸舱面在 Docker Desktop 上必须绑 `0.0.0.0`（网桥地址在虚拟机里，
  宿主绑不上），目前靠**舱令牌**把关；「来源必须是容器网段」这道第二层校验仍在进行中。
  在它落地之前，不要把气闸暴露到不可信的网络里。

## 平台与形态

| 项 | 状态 |
|---|---|
| macOS 桌面版 | V1 **唯一**的目标平台 |
| Windows 桌面版 | ❌ 不做 |
| Linux 桌面版 | ❌ 不做。核心逻辑与测试在 Linux 上跑得通，但那不是产品形态 |
| 命令行 | ❌ 不做。入口只有托盘 |
| 账号 / 团队 / 云同步 | ❌ 不做 |
| 遥测上报 | ❌ 不做 |

**Linux 支持到什么程度**：`packages/core` 与工具链在 Linux 上通过测试，`docker` 后端也能在 Linux
上起容器；但托盘、拖放、面板都是 macOS 语义，**没有 Linux 桌面版**。`local` 后端在 Linux 上同样
只是「验证编排逻辑」的开关，不是沙箱。

## 现在还没落地的

这些是产品设计里有、当前版本还没有的能力。使用手册按目标行为描述它们，这里如实列出缺口：

| 能力 | 现在是什么样 |
|---|---|
| 公开发布的安装包 | 没有。只能从源码运行或自行打包；产物是 ad-hoc 签名、未公证 |
| 每个 agent 自己的镜像 | 清单里还没有这一项；统一用 `session.image` 的默认镜像 <code>{SESSION_IMAGE_FALLBACK}</code>，它**不包含**任何 agent 的 CLI |
| 跨舱保留 agent 历史 | 清单里还没有历史目录（`statePaths`）；舱退出后 agent 自己的会话历史会丢 |
| 生产形态只接 OSW | 仍在落地；示例配置还保留三个直连上游作为开发期能力 |
| 共享区 / 取回区的完整挂载语义 | 面板能接住拖放并显示条目，真正的挂载与出舱确认仍在接入 |
| 舱面来源网段校验 | 进行中，见上一节 |

## 还没在真机上验证的

下面这些**不许当成已通过**：

- **macOS 真机**：现有隔离结论是在 Linux 版 Docker Desktop 上测的；macOS 的共享路径默认值与
  虚拟机网关地址可能不同，必须重跑。
- **真实 agent 二进制**：舱内跑的一直是替身脚本，不是真的 Claude Code / Codex / dsh。
- **真实 agent 的出网域名集合**：默认拒绝下，白名单大概率要一条条补；补哪几条只能靠实测。
- **Claude Code 的多行自定义请求头**：按 `Name: Value` 换行分隔实现，尚未对着真实行为核实。
- **Codex 的登录态**：走的是另一套机制，尚未实测。
- **dsh**：命令名、环境变量名与配置字段名都缺少权威来源，清单里标为「待确认」。
- **对抗性测试**：还没有系统性地尝试绕过白名单、伪造舱令牌、从舱内往外打。
- **Electron / 托盘拖拽**：开发机没有图形会话，托盘的失焦隐藏、贴图标定位与 `drop-files` 落点
  都还没在真机上看过。

## 故意不做

- 不做自己的沙箱内核（用 Docker）。
- 不做跨平台全支持。
- 不做细粒度策略图形编辑器与企业策略分发。
- 不做「完整设置中心」塞进托盘；面板只回答三个问题。
- 不做系统级代理：只有显式把请求发到气闸的客户端才受管，abx 不劫持系统流量。
