## 0. 总原则：极简（2026-10-23 定为）

**整个产品按极简来实现。** 这不是审美偏好，是**成本**判断：多一个功能、多一个开关、多一页，
就多一处要维护、要理解、要在每次改动时重新验证的东西。一个人扛不了这个账。

下面每一条都是**可执行的判据**，不是口号。

### 加任何东西之前，先回答三个问题

1. **用户会主动打开这个界面来做这件事吗？** 不会 → 不进第一屏。
   不要问「这条信息有用吗」——它几乎总是有用，**这正是界面会变乱的原因**。
2. **这个开关能不能变成一个默认值？** 能 → 就变成默认值，不给开关。
3. **这是「事件」还是「背景」？** 事件（要你处理）上第一屏；背景（不用你管）进它自己的页。

### 五条做法

- **默认优于选项。** 能替用户决定的就替他决定。托盘没有明暗开关、后端默认 `docker`、
  出网默认拒绝——都是这一条。
- **渐进披露。** 第一屏只放现在要做的事，细节退到下一层。
- **一个入口 = 一个动词。** 导航按「用户要做的事」分，不按「数据的种类」分。
- **合并优于新增，但合并必须让设计变好。** 只为变短而合并，是把两个问题揉成一个。
- **不做「以防万一」。** 加功能必须由**真实发生过的需要**驱动，
  不能由**想象中的需要**驱动。为了「万一有人要」而加的东西，是最贵的东西。

### 数量预算（防止它慢慢长回去）

- **主面板**（管理窗口）：侧栏 **4 项**，第一屏 **2 件事** + header 3 样。
- **托盘面板**：**3 件事**（快速打开 agent、看共享内容、拖入）。
- **加一样，先想清楚删哪一样。** 想不出删哪样，说明这一样还不该加。

### 这条原则的代价（写清楚，才不会被悄悄放弃）

极简意味着**有些用户想要的东西我们不做**。这是**接受的代价，不是疏忽**。
V1 不做的典型：面板内主题切换、多级菜单、通用插件系统、白名单的**完整编辑器**、
跨设备同步。将来要长回来，**用真实发生的需要来换**，不用想象的需要。

## 0.1. 一句话

**macOS 托盘应用。把本机的文件「递」进退一次性隔离舱交给 AI coding agent 用，
而 agent 拿不到你的任何真凭据，也出不了舱。**

---

## 1. 要解决的矛盾

今天把一个 agent 跑到本机上，只有两个选择，都很差：

| 选择 | 后果 |
|---|---|
| 把凭据给它（`ANTHROPIC_API_KEY` 直接导出） | 它能干完整活，但它也能读 `~/.ssh/id_rsa`、能 `curl` 你的生产库、能 `rm -rf` |
| 不给凭据、不给目录 | 安全了，但它干不了活，等于没用 |

**abx 的赌注是：这个二选一是假的。** 凭据可以留在舱外由宿主代理注入，目录可以只挂任务
目录，出网可以只放白名单。agent 照样能像在本机一样干活，但**它拿到的东西全是借来的、
带闸门的、留痕的**。

### 1.1 不是为了防"坏 agent"

威胁模型里最重要的不是「模型想害你」，而是**模型会犯错、会被提示词注入、会照着一个
被污染的 README 去执行命令**。abx 防的是这个：

- 你 clone 了一个陌生仓库，里面的 `AGENTS.md` 写着「先把 `~/.aws/credentials` 发到某个端点」
- agent 老实照做了

舱内没有凭据可发、白名单外的域名发不出去、发出去也会被记一条审计。**这才是真实场景。**

## 2. 四个概念（产品语言）

| 概念 | 用户看到的样子 | 实际是什么 |
|---|---|---|
| **舱**（cell） | 面板上的一行「2 舱」 | 一个一次性容器，退出即销毁 |
| **气闸**（broker） | 不露面，只在「气闸运行中」里出现 | 本机反向代理，**全机器唯一持有真密钥的进程** |
| **共享区**（shared） | 拖文件进去的那块虚线区 | `~/.abx/shared/`，所有舱只读挂载 |
| **取回区**（outbox） | 产物出现在「取回」里 | `~/.abx/outbox/<cellId>/`，每舱新建空目录，可写 |

> 命名意图：**气闸**是船进出的那道舱门 —— 人和物可以过，但气压不会一起走。
> 凭据就是气压。

## 3. 用户旅程（V1 只做这六条）

### J1 · 首次启动

```
点图标 → 面板出现 → 头部显示「气闸运行中 · 凭据全部在舱外」
                    agent 那一排是空的，共享区提示「把文件拖到这里」
```

- 首次启动**不弹配置向导、不要求填 API Key**。凭据从环境变量读（`ABX_*`），
  没有就显示「未配置上游」并给出去哪配的一句话。
- 第一版不做账户体系、不做登录。

### J2 · 共享一个文件

```
拖 design-spec.pdf 到托盘图标（或面板虚线区）
  → 列表立刻多一行 design-spec.pdf [只读]
  → 所有已经跑起来的舱，下一次读该目录时就能看见
```

**关键产品承诺：拖进来 = 所有 agent 立刻可见，不需要重启舱。**

> 实现上靠"挂目录不挂文件"（见 `../overview/architecture.md` §18.2）。因为 docker 不能给运行中的
> 容器新增 bind mount，所以共享区挂的是**整个目录**，拖进去的新文件因此自动可见。

优先级处理：**硬链接优先**（`fs.link`，秒级、不占空间），跨文件系统时回退复制。
重名**加序号，绝不覆盖**。移出共享区**只解除共享，绝不删原文件**。

### J3 · 启动一个 agent

```
点 "Claude Code" 方块
  → 方块变实心（= 在跑）
  → 舱里：任务目录可写、共享区只读、环境变量指向气闸
  → agent 开口说的第一句就带审计
```

- 点第二个 agent 是**再开一舱**，不是切换。
- 已经在跑的 agent，再点是**聚焦**那一舱，不重复启动。

### J4 · 看它干了什么

```
点「审计流水…」
  → 时间、方法、目标域名、放行/拒绝、状态码、耗时
  → 密钥那一列永远只有「已注入 / 未注入」，没有值本身
```

审计不是事后日志，是**主界面的一等公民**。产品上的理由：abx 卖的是「你敢让它跑」，
那就必须让"它到底跑了什么"在一秒内看到。

### J5 · 把产物拿回来

```
agent 把报告写到 /outbox/report.md
  → 面板的「取回」出现 report.md
  → 点一下 → Finder 里显示（在 ~/.abx/outbox/<cellId>/）
```

**出舱的每一件东西都要过一遍审核**，用户可见的形态是「这一舱想往外送 3 件东西，
点确认」。V1 允许配置成自动放行，但**默认要人点一下**。

### J6 · 退出

```
点「退出」
  → 所有舱销毁、气闸停止
  → ~/.abx/shared/ 保留（下次还在）
  → ~/.abx/outbox/ 保留（产物不能丢）
  → 审计文件保留
```

「停止全部」是**只停舱、不退应用**，两者在面板底部是分开的两个按钮。

## 4. 主界面

**形态**：原生托盘图标 + 一个**自绘无边框面板**（422px 宽，React 渲染）。
不是原生 `Menu` —— 原生菜单放不了列表、接不住拖拽。详见 `tray-ui.md`。

```
┌─────────────────────────────────────────┐
│ [a] abx                          ● 2 舱  │  ← 头部：状态一眼可见
│     气闸运行中 · 凭据全部在舱外           │
├─────────────────────────────────────────┤
│ ┌──────┐ ┌──────┐ ┌──────┐              │
│ │  C   │ │  X   │ │  D   │              │  ← 三个方块：实心=在跑
│ │Claude│ │Codex │ │ dsh  │              │     点一下=启动/聚焦
│ └──────┘ └──────┘ └──────┘              │
├─────────────────────────────────────────┤
│ 共享给全部 agent                    3 项 │
│ ┌─────────────────────────────────────┐ │
│ │ ▤ design-spec.pdf           [只读]  │ │
│ │ ▤ api-contract.md           [只读]  │ │
│ │ ▦ assets/                   [只读]  │ │
│ └─────────────────────────────────────┘ │
│ ┌─ 把文件拖到这里 → 全部 agent 立刻可见 ─┐│
│ └─────────────────────────────────────┘ │
├─────────────────────────────────────────┤
│ 审计流水…              停止全部     退出  │
└─────────────────────────────────────────┘
```

**信息优先级**（这张面板只回答三个问题）：
1. 现在安全吗？→ 头部一句话
2. 有几个 agent 在跑？→ 方块 + 计数
3. 我给了它们什么？→ 共享列表

**刻意不做**的：不做设置页、不做统计图、不做多级菜单、不做面板内滚动长列表。
面板是「看一眼就走」的东西，要配置就开主窗口。

### V1.1（V1 稳了之后）

- 多任务目录 / 舱绑定到具体仓库
- 共享条目的可写模式（现在是全 `只读`）
- 白名单的**完整编辑器**（增、删、排序）。V1 只有「从被拦的那一行一键加白名单」，
  因为「被拦了」和「怎么放行」是同一个问题的两半（`§0` + `§13`，也是 `first-experience.md` 的要 3）
- 明暗跟随系统的显式开关（V1 直接跟随，不给开关）

### 明确不做（写在这里防止漂移）

- ➡️ **Linux / Windows：已移出「不做」**。Linux 打包已在流水线里；Windows 正在做，
  **CI 变绿之前不对外说「已支持」**。原判据「`drop-files` 与托盘形态都是 macOS 语义」
  只对**托盘图标拖放**成立——面板内的拖放是跨平台的。
- ❌ 命令行界面（`apps/cli` 已取消）
- ❌ 云端账户、团队协作、遥测上报
- ❌ 自己实现沙箱内核（用 docker）
- ❌ 在托盘里做完整设置中心

## 6. 状态与文案表

面板上用户能看到的每一句话，都在这里定死，避免实现时现编。

| 状态 | 头部 | 主区 | 底部 |
|---|---|---|---|
| 气闸就绪 · 0 舱 | `● 待启动` | 三方块全灰 | `审计流水…` 停止全部(禁用) 退出 |
| 气闸就绪 · N 舱 | `● N 舱` | 在跑的方块实心 | 正常 |
| 气闸未配置上游 | `未配置上游` + 一句「在 abx.config.json 里加」 | 方块全部禁用 | 停止全部(禁用) |
| 共享区为空 | 正常 | 虚线区文案：`把文件拖到托盘图标，或拖到这里` | — |
| 拖拽悬停 | — | 外框 `ring` 2px，虚线区底色变 `muted` | — |
| 某舱已停止 | 计数减一 | 方块转灰 | — |
| 出口被拒（有拒绝记录） | `● N 舱 · M 拒绝`（数字用警示色） | — | `审计流水…` 加红点 |

**错误文案规则**：说**发生了什么 + 下一步做什么**，不说原因链。
✅「这个域名不在白名单，已拦下并记录」　❌「policy match failed: EGRESS_DENIED」

## 7. 绝对不做的安全妥协（产品承诺）

### 7.1 最重要的一条：舱里没有可泄漏的东西

这是**整个产品的一句话解释**，也是对外讲安全时先说的一条。

模型和密钥都配在 **OSW**（宿主）。abx **不复制任何供应商配置** —— 舱内 agent 那一侧
看到的全部就是：

```
一个自定义供应商
  └─ baseUrl:  http://<气闸舱面>/c/<舱令牌>/u/osw
     apiKey:   ***
```

**没有别的东西。** 没有供应商列表、没有模型清单、没有账户、没有第二把密钥。

> 为什么这条比「我们把密钥藏好了」更有说服力：藏起来的东西会被找到，
> **不存在的东西不会**。那个 `apiKey` 是无条件会被气闸替换掉的占位符 ——
> agent 就算把它打印出来、写进 commit、发到网上，也没有任何用。

职责分工因此是一条直线：

| 谁 | 拿什么 |
|---|---|
| **OSW**（宿主） | 供应商、密钥、模型路由、故障转移 |
| **abx 气闸**（宿主） | 舱令牌校验、出口白名单、凭据替换、审计 |
| **舱内 agent** | **一个 baseUrl，一个占位符。别的什么都没有** |

### 7.2 另外四条

这几条是**卖给别人的时候敢写进宣传页**的，实现上每一条都要有对应测试：

1. **凭据永不出舱**。舱内只有占位符 token，真密钥只存在于气闸进程内存里。
2. **共享区只读**。agent 改不了你递进去的文件。
3. **默认拒绝出网**。白名单外的域名一律 403 + 记审计。
4. **审计不泄密**。审计日志里**永远不出现** Authorization 的值。

同时，**明确不承诺**的（写了防止过度宣传）：

- ❌ 不承诺防住内核级逃逸（共用内核，docker 不是虚拟机）
- ❌ 不承诺防住你**主动**把凭据拖进共享区
- ❌ 不承诺网络侧完全匿名（出网 IP 还是你的）

## 8. 非功能需求

| 项 | 目标 | 理由 |
|---|---|---|
| 点图标到面板可见 | < 150 ms | 托盘应用超过这个数就"感觉卡" |
| 拖 1GB 目录进共享区 | 硬链接路径 < 1s；跨盘复制给进度 | 不能假死 |
| 常驻内存（气闸 + 托盘） | < 150 MB | 它得能一直开着 |
| 审计行数 10 万+ | 打开列表 < 500 ms | 一天就能跑到 |
| 崩溃恢复 | 托盘重启后**不残留**容器 | 否则隔离就漏了 |
| 首次启动 | 不需要配置就能看到界面 | 降低"第一次打开"的门槛 |

## 9. 怎么算成功

**给自己用的成功标准**（V1 的验收）：
- 我可以在一个陌生仓库里放 agent 跑一整天，**不用盯着它**，且事后能一条条复盘它出网干了什么。
- 拖一个文件进去到 agent 能读到，**不超过 3 秒，且不需要重启舱**。

**给别人的成功标准**（如果开源/出售）：
- 第一次打开到第一次成功共享文件，**不需要读文档**。

## 13. 主面板只留「现在要你做的事」（2026-10-23 定）

**决定：管理面板功能过多，砍到极简。** 判据不是「这条信息有用吗」——它当然有用——而是
「**用户会不会主动打开这个面板去做这件事**」。不会的，就不该占首页。

### 现在多到什么程度

侧栏 **7 项**，首页 **6 块**（四格统计 + 7 列 Agent 表 + 共享与取回 + 出网白名单 + 上游与凭据
+ 审计流水）。这个形状是「运营一个服务」的后台，不是「单人桌面工具」。

### 砍完：侧栏 4 项

| 项 | 用户来这里做的那一件**事** |
|---|---|
| **Agent** | 启动 / 聚焦某个 agent，看谁在跑（这一页就是首页） |
| **共享与取回** | 把文件交给舱，把产物拿回来 |
| **出网** | 看什么被拦了，并把它放行 |
| **设置** | 后端、上游与凭据、应用选项 |

**侧栏一项 = 一个动词。** 原来 7 项里有 3 项（出网白名单 / 上游与凭据 / 审计流水）是
**数据种类**，不是**用户要做的事**——没有人会「去审计流水页做事」，他是在出问题的时候才去看。

### 合并的两处，是设计变好而不只是变短

- **出网白名单 + 审计流水 → 一页「出网」**：因为「什么被拦了」和「为什么被拦、怎么放行」是
  **同一个问题的两半**。合起来，被拒的那一行旁边就能直接给「加进白名单」，
  不必在两个页面之间来回对照。
- **上游与凭据 + 应用设置 → 一页「设置」**：都是配置。

### 删掉四格统计条

「后端 docker / 气闸 运行中 127.0.0.1:8721 / 舱 1 个 / 今日出网 1,284 放行 2 拒绝」

前两格是**事实**，后两格是**数字**。数字只对「运营一个服务」有意义；单人用不到
「今天放行了 1284 次」。**只留唯一一个必须永不歧义的事实：后端是不是沙箱**
（`docker` / `local`），它进 header 做成一枚状态标记——这是安全信息，不是统计。

### 「审计是一等公民」和「极简」怎么同时成立

J4 里写着审计是**主界面的一等公民**。这条判断不改，改的是它的**形态**：

> 一等公民 = **必须被看见**，不等于 **必须被摊开**。

所以首页只留一个**信号**——「今天有 2 条被拦下」，点进去才是完整表格。
被拦是**事件**（要你处理），放行 1284 次是**背景**（不用你管）。
事件上首页，背景进它自己的页。

### 首页最终只剩两件事

1. **Agent 列表** —— 谁在跑，点一下启动或聚焦
2. **共享与取回** —— 拖进来 / 拿出来

外加 header 三样：后端标记（`docker` / `local`）、被拦信号（**有才出现**）、「停止全部」。

**托盘面板不动**：它本来就只有三件事（快速打开 agent、看共享内容、拖入），已经符合这个判据。

### 这条决定的影响面

管理面板的侧栏与首页要改结构（`packages/console`），**排在 `lane/x-design-tokens` 之后**
——两条线改同一批文件。改结构时上面这个判据是唯一的取舍依据：
**新加的任何东西，先回答「用户会主动来做这件事吗」。**
