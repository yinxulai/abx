# 官网（`apps/www`）

**这一份写什么**：官网与文档站的分工、版块顺序、双语策略、agent 数据的单一来源、
视觉与可访问性的机器判据。

**这一份不写什么**：做到哪一步。进度与验收状态只在
[`../../roadmap.md`](../../roadmap.md) 里，官网也不维护第二份（见 §六）。

---

## 一、分工：官网说服，文档站教怎么用

| | 回答的问题 | 读者 | 位置 |
|---|---|---|---|
| **官网** | 为什么该用它、它挡住什么、不挡住什么、上手是什么样 | 还没决定用不用的人 | `apps/www` |
| **文档站** | 每一条怎么配、怎么验、现场怎么排错 | 已经在用的人 | `apps/docs`（`source/`，尚未开写） |

判据很简单：**一句话读完之后，读者要做的动作**。

- 官网的动作是「继续往下读 / 决定试一下」——所以官网只给**结论**。
- 文档站的动作是「照着做」——所以文档站给**步骤**。

因此跨内容只写**一句结论 + 指路**，不复制。举两个已经落地的例子：

- 平台支持程度只在「边界」一节讲（`boundaries.tsx`），下载区只写一句「其它平台见边界那一节」。
- 「第一步怎么装」在官网只写结论与那次 Gatekeeper 拦截，逐步的验收清单留在
  [`first-experience.md`](./first-experience.md)。

官网里凡是**能被规格文档回答**的句子，都在组件注释里标了出处（`specs/...` 的哪一节），
改文案时顺着注释回去核对，而不是凭印象。

## 二、版块顺序

顺序即叙事，`App.tsx` 里那一行 `<main>` 就是全文的目录：

| # | 区块 id | 回答什么 | 组件 |
|---|---|---|---|
| 1 | 无 id（首屏不参与锚点导航，顶栏品牌回到 `#main`） | 这是什么 | `hero.tsx` + `tray-panel-preview.tsx` |
| 2 | `#model` | 为什么它敢说「密钥不进舱」 | `credential-model.tsx` |
| 3 | `#agents` | 能跑哪些 agent、各自的镜像与持久化目录 | `agent-overview.tsx` |
| 4 | `#start` | 从下载到把一个目录递进去 | `getting-started.tsx` |
| 5 | `#boundaries` | 默认值、明确不承诺什么、各平台到什么程度、什么情况下不适用 | `boundaries.tsx` |
| 6 | `#faq` | 决定用不用之前一定会问的八件事 | `faq.tsx` |
| 7 | `#changelog` | 发布过什么 | `changelog.tsx` |
| 8 | `#download` | 现在能不能下载 | `download-section.tsx` |

第 5 节的位置是刻意的：**先讲挡住什么，紧接着讲不挡什么**。中间隔一节，
读者就会先自己把「挡住这些」外推成「挡住一切」。

## 三、双语：中文是原文，英文是翻译

与 OSW 的官网同一套（见 `osw/apps/www/source/i18n.ts`）：

- **中文不建资源表**，写在 `t(key, '中文文案')` 的第二个参数里，就写在用到它的组件里 ——
  改文案和改代码在同一处。
- **英文在 `i18n.ts` 的 `en` 表**里增量补。缺哪一句，那一句就还是中文：
  不是空白、不是 key、更不是 404。站点是单页，没有 `/en` 这样的路径。
- `i18n.test.ts` 扫源码里所有静态 `t()` 的 key，逐个比对 `en` 表；数据表驱动的文案
  （FAQ 条目、原则卡片）取不到字面量，另列在 `DYNAMIC_TRANSLATION_KEYS` 里。
  **所以漏译一句的结果是测试红，不是上线后被人发现。**

两处 pin：

| 参数 | 用途 |
|---|---|
| `?theme=light\|dark` | 截图、评审、分享一条固定外观的链接 |
| `?lang=zh\|en` | 同上，针对语言 |

语言优先级：URL > localStorage > `navigator.language` > 中文兜底。
`index.html` 里那段首帧脚本读的是同一套顺序 —— 两边不一致会「先中文后英文」闪一下。
有了 `?lang=` 才可能用无头浏览器拍到中文页（它报的是 `en-US`）。

## 四、Agent 数据只有一个来源

`apps/www/source/agents.ts` **import** `packages/contracts/source/agents.ts` 的
`AGENT_DEFINITIONS`，页面上的每一个值都从清单里取：

- 舱内命令、默认上游、舱内变量、占位符、舱令牌怎么走、配置文件 —— 全部直接读清单字段；
- **镜像**与**持久化目录**：这两个字段目前还不在清单里（见
  [`../overview/agent-manifest.md`](../overview/agent-manifest.md) §二，p 线正在把它们移进清单）。
  官网的处理是：
  - 读得到就显示（`readImage()` 做类型守卫，字段到位后页面自动跟着变）；
  - 读不到就**如实写「清单未按 agent 指定」**，绝不去借一个全局默认值冒充；
  - 持久化目录先按清单里**该 agent 自己的配置文件**的父目录推导
    （`~/.claude/settings.json` → `~/.claude`），并在页面上注明「按舱持久化还在实现中」。

`agents.test.ts` 断言的不是「页面长什么样」，而是**页面上的值等于清单里的值**，
以及三个推导结果（`~/.claude` / `~/.codex` / `~/.dsh`）。手抄一份数据是不可能通过这个测试的。

> 为什么这么在意：手抄的那份一定会在某次 agent 升级后漂移，而漂移的方向永远是
> 「页面还在说旧的」，这是最难被发现的一类错误。

## 五、视觉与可访问性：判据是量出来的

### 5.1 怎么跑

```bash
pnpm --filter @abx/www build
pnpm --filter @abx/www preview --port 4177 --strictPort   # 产物在 output/，路径是绝对的，必须走 HTTP

S=~/.openclaw/workspace/skills/design-review-loop/scripts
bash $S/shot.sh "http://localhost:4177/?theme=dark&lang=zh" apps/www/.state/x.png 1440x900
node $S/audit.mjs "http://localhost:4177/?theme=light&lang=zh" --viewport 390x844
```

- **截图与审计报告落在 `apps/www/.state/`，已在 `.gitignore` 里，不进仓库。**
- audit 退出码：`0` 无致命项，`1` 有致命项，`2` 运行错误。

### 5.2 判据（`audit.mjs` 里真正会判红的）

| 类型 | 阈值 | 级别 |
|---|---|---|
| 正文对比度 | < 3:1（AA 要求 4.5） | 🔴 |
| 横向溢出 | > 1px | 🔴 |
| 触控目标（≤480px 视口） | < 44×44 | 🔴 |
| 缺 `<meta name="viewport">` | — | 🔴 |
| 对比度 | 3:1 ~ 4.5:1 | 🟡 |
| 文字被裁剪 | 任意一处 | 🟡 |
| 触控目标（桌面） | < 24×24 | 🟡 |
| 字号档位 | > 6 级 | 🟡 |
| 最小字号 | < 11px | 🟡 |
| 间距离 4px 栅格 | > 3 个值 | 🟡 |

### 5.3 实测（2026-10-23）

八个组合（`1440x900` / `390x844` × 深/浅 × 中/英）**全部退出码 0，0 红 0 黄 0 绿**；
每个视口实测 245～247 个文本节点，`contrastSkipped` 为 0。

字号档位：桌面 60 / 36 / 18 / 16 / 14 / 12，手机 36 / 30 / 18 / 16 / 14 / 12 —— 都是 6 级。

两套主题的语义色两两对比度（最低的一格是浅色下 `mint`/`amber` 落在 `surface-1` 上）：

| token | 深色 · surface-0 / surface-1 | 浅色 · surface-0 / surface-1 |
|---|---|---|
| `ink` | 17.95 / 17.02 | 18.92 / 17.04 |
| `ink-2` | 13.56 / 12.86 | 11.13 / 10.02 |
| `ink-3` | 9.31 / 8.82 | 6.77 / 6.09 |
| `ink-4` | 5.38 / 5.10 | 5.47 / 4.92 |
| `ice` | 11.66 / 11.06 | 5.93 / 5.34 |
| `mint` | 11.16 / 10.58 | 5.02 / 4.51 |
| `rose` | 7.23 / 6.85 | 6.29 / 5.66 |
| `amber` | 11.65 / 11.05 | 5.02 / 4.52 |

全部 ≥ 4.5:1。浅色那四个强调色**必须**和深色分开取值：冰蓝这类亮色直接放到白底上
只有 1.6～2.5:1，连 3:1 都不到 —— 这是浅色方案最容易带着一起搬过去的错误。

### 5.4 被判据逼着改掉的三处（都是真问题，不是判据的问题）

1. **手机上的语言开关 40px 高**（`py-3` 加 12px 行盒）。差 4px 就是点不准。
   现在 `min-h-11`，宽屏收回 24px。
2. **字号多出第 7 档**：下载区一个 `text-xl`（20px）夹在 18px 的行里，
   没人选过这个值。现在收敛到 6 档。
3. **`sr-only` 让「跳到主要内容」量出来是 1×1**：它压成 1px 再裁掉，
   于是审计读成「文字被裁剪」+「1×1 的可点目标」，表格的 `<caption>` 也一样。
   两条都不是真缺陷，但每次评审都要重新解释一遍。现在改用 `off-screen`
   （绝对定位挪到可视区外）：元素保持自然尺寸、照样留在无障碍树里，
   跳过链接在 `:focus` 时用 `focus:fixed` 回到视口里。

### 5.5 已知不在判据内、但人要看的

- **版式与气质**（留白、层级、有没有「一眼假」）：`audit.mjs` 量不出来，靠截图。
- **文案是否成立**：机器判不了，靠组件注释里标出的规格出处去核对。
- 量不出来的那部分，截图路径与结论写在每次的交付说明里，不写在这里。

## 六、刻意不做的事

- **不放外链**：仓库目前是私有的，放一个 404 的仓库/文档链接等于自己拆台。等公开再加。
- **不放占位下载按钮**：没有产物就是「尚未提供」，一个点了没反应的按钮比没有按钮更糟。
  `App.test.tsx` 与 `download-section.test.tsx` 都断言下载区**没有** `link` / `button`。
- **不维护第二份进度**：更新日志只记**发布过什么**，逐条实现程度只写在
  [`../../roadmap.md`](../../roadmap.md)。两份进度表一定会漂移。
- **不做手册**：官网出现「第三步点哪里」这种句子时，说明这条内容该去文档站了。

## 七、页面上的限制是怎么写出来的

凡是没做到 / 没验证的，页面**主动写**，不留给读者自己踩：

- agent 一览：镜像与持久化目录「还没有」，并说明为什么；
- 边界：五条明确不承诺（含「还没有做过对抗性测试」）；
- 平台：macOS 尚未真机验证、Linux 的 `local` 后端「不是沙箱，禁止用于演示」、Windows 不做；
- 更新日志：一条「未发布」，范围 ≠ 成绩单，且**不编日期**（有测试断言不出现日期）；
- 下载：没有安装包，放行 Gatekeeper 的那一步也如实写着。

理由在 `boundaries.tsx` 的注释里：主动写清限制比藏起来更能建立信任 ——
而且这些限制本来就是读者迟早会撞上的东西。
