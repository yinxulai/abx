# 设计体系（令牌层）

这份文档是**骨架、颜色、字号、间距、圆角、状态表达**的唯一来源。托盘面板与管理面板共用它——
两个面板是同一个产品，不该各有一套观感。

令牌的实现落在 `packages/console/source/styles.css` 的 CSS 变量里。**改这份文档不等于改产品**，
两边必须一起动；`styles.test.ts` 会拿这份文档的表格和样式表对账，对不上就红。

---

## 1. 五条原则

**1. 骨架完整，密度克制。** 「极简」不是「去掉骨架」。骨架是**让用户不必点进去就知道发生了什么**
——标题栏上的状态、每一块的说明句、每一行右端的动作位。密度（放几条记录、几列数据）可以省，
骨架不能省。省掉骨架的界面看起来像网页，用起来要用户自己找状态。

> 这条是 2026-10-23 用一次失败的稿子换来的：v4 把「少」理解成「去掉结构」，
> 于是状态被藏进每一行 agent 里——而托盘应用的整个价值就是「不用进去也知道在不在跑」。
> **照抄 osw 的骨架是对的，照抄它的密度是错的**（osw 有 841 条请求日志，abx 没有）。

**2. 中性底，彩色极省。** 界面几乎无彩色。**允许出现的彩色只有两处**：

| 色 | 只允许用在这两件事上 |
|---|---|
| `--accent` | ① 运行中的图形（状态点、运行中的方块描边/底）② 焦点环 |
| `--danger` | ① **真的会毁东西**的动作（停止全部、删除）② 被拦下的事件 |

**主按钮不用点缀色**，用**前景色实心**（浅色下近黑底白字，深色下近白底深字）。
「未运行」「未构建」「空闲」「已停止」**一律不用彩色**——它们不是错误，是正常状态。

**3. 颜色永不单独承载信息。** 运行中不只是一个色块，还有实心形状与文字；危险不只是变红，
还有图标与措辞。色觉差异的用户必须同样能读懂状态。

**4. 边界分两档，因为它们承担的责任不同。** 装饰性分隔线可以很淡；
**用来识别一个控件的边界**（拖放区的虚线、输入框）必须 ≥ 3:1，否则它等于没画。

**5. 文字分四级。** 每一级都有归属，不许出现「这一行每个字都一样重」的界面。
四级各自的取值与用法见 §2。

## 2. 颜色令牌

数值是实测结果，不是估的。比值按 WCAG 2.1 相对亮度计算。
**每一级文字都同时在三种底上量过**：窗口（`--bg`）、卡片（`--surface`）、浮起块（`--raised`）。

### 深色

| 令牌 | 值 | 用在哪 | 实测对比度 |
|---|---|---|---|
| `--bg` | `#191A1C` | 窗口底（标题栏也是它） | — |
| `--surface` | `#232427` | 卡片 | — |
| `--raised` | `#2B2C2F` | 浮起块：悬停、中性胶囊底 | — |
| `--border` | `#35373B` | **装饰性**分隔线 | 1.30:1（不为信息负责，故豁免） |
| `--border-strong` | `#7E8288` | 有意义边界（拖放区、输入框） | surface **4.02:1** / bg **4.51:1** |
| `--text-primary` | `#F2F3F4` | 标题、行主名 | surface **13.97:1** / bg **15.68:1** / raised **12.57:1** |
| `--text-secondary` | `#C6C8CD` | 正文、行内次要信息 | surface **9.27:1** / bg **10.40:1** / raised **8.34:1** |
| `--text-tertiary` | `#A8AAB0` | 区块说明句 | surface **6.68:1** / bg **7.50:1** / raised **6.01:1** |
| `--text-quaternary` | `#92949A` | 时间戳、计数、空心态 | surface **5.12:1** / bg **5.74:1** / raised **4.60:1** |
| `--accent` | `#3FD9C6` | 运行中图形 / 焦点环 | surface **8.83:1** / bg **9.91:1** |

### 浅色

| 令牌 | 值 | 用在哪 | 实测对比度 |
|---|---|---|---|
| `--bg` | `#FAFAFA` | 窗口底（标题栏也是它） | — |
| `--surface` | `#FFFFFF` | 卡片 | — |
| `--raised` | `#F1F1F2` | 浮起块：悬停、中性胶囊底 | — |
| `--border` | `#E2E2E5` | **装饰性**分隔线 | 1.29:1（豁免） |
| `--border-strong` | `#82848A` | 有意义边界 | surface **3.74:1** / bg **3.58:1** |
| `--text-primary` | `#1A1B1D` | 标题、行主名 | surface **17.24:1** / bg **16.51:1** / raised **15.27:1** |
| `--text-secondary` | `#3F4147` | 正文、行内次要信息 | surface **10.20:1** / bg **9.77:1** / raised **9.04:1** |
| `--text-tertiary` | `#55575D` | 区块说明句 | surface **7.22:1** / bg **6.92:1** / raised **6.40:1** |
| `--text-quaternary` | `#6B6D74` | 时间戳、计数、空心态 | surface **5.17:1** / bg **4.95:1** / raised **4.58:1** |
| `--accent` | `#0E8C80` | 运行中图形 / 焦点环 | surface **4.13:1** / bg **3.96:1** |
| `--accent-deep` | `#0A7268` | 运行中胶囊的**字** | surface **5.80:1** / accent-soft 上 **5.14:1** |
| `--accent-soft` | `#E7F4F1` | 运行中胶囊底 | — |
| `--danger` | `#C0362C` | 危险动作 / 被拦 | surface **5.52:1** |
| `--danger-soft` | `#FBECEA` | 被拦胶囊底 | `--danger` 字压在上面 **4.81:1** |

**为什么浅色下点缀色有两个值**：同一个色相在深底上够亮、在白底上就不够。
`#0E8C80` 当图形是够的（4.13 ≥ 3），当正文不够（< 4.5），所以**胶囊里的字**用 `#0A7268`。
**不要用 `--accent` 在浅色下写正文**——那是这份文档里最容易犯的错。

深色下没有第二档：`--accent` 一个值当图形和正文都够。所以深色里 `--accent-deep` 是
`var(--accent)` 的**别名**——这一行不能省，`:root` 里已经定义过浅色那一档，
不显式覆盖的话深色会安静地继承那支墨绿（实测只有 2.68:1）。这是真发生过的错，不是理论问题。

### 四级文字：谁用哪一级

| 级别 | 管什么 | 例子 |
|---|---|---|
| primary | 标题、行主名、区块标题 | 卡片标题、agent 名、文件名 |
| secondary | 正文、行内次要信息 | 「目录 · 只读」、设置项的值 |
| tertiary | 区块说明句 | 标题下面那行解释「这会影响到什么」 |
| quaternary | 时间戳、计数、空心态、禁用 | 「5 项」、`12:04`、空心状态圈 |

**四级之间是递进关系，不是四套并列的花色。** 同一块里最多出现三级：
标题 primary、说明 tertiary、元信息 quaternary。

> ⚠️ **浅色下第四级的可用空间比深色窄，这是实测结论不是感觉。**
> `--text-quaternary` 在浅色下最浅只能到 `#6B6D74`（4.58:1 @raised）；再浅一档就没有
> 合法取值空间了。深色下同一级还有更多余量。所以**浅色下 tertiary 与 quaternary 的
> 视觉差距比深色下小**——这是 AA 门禁换来，不是取色取坏了。
> `tray-ui.md` §2.3 里原来的三级方案写的理由（「比 muted 更弱没有合法空间」）**方向反了**：
> 它当时找的是「`foreground` 的透明度」，那条路上确实没有空间；把第四级定成一个**绝对色值**
> 就有了。

### 彩色只出现在两处（可执行的判据）

写完一个界面，数一遍：出现 `--accent` 的地方不超过 **运行中** 和 **焦点环**；
出现 `--danger` 的地方不超过 **会毁东西的动作** 和 **被拦下的事件**。
多出来的每一处都要先回答「它为什么不是中性色」。

## 3. 字号与字重

英文与数字用 `Geist Variable`（回退 `-apple-system` / `SF Pro Text`），中文回退 `PingFang SC`，
等宽（路径、版本号、id）用 `Source Code Pro` → `SF Mono` → `ui-monospace`。

| 令牌 | 字号 | 行高 | 用在哪 |
|---|---|---|---|
| `--text-2xs` | 11 | 14 | 徽标、计数、状态胶囊 |
| `--text-xs` | 12 | 16 | 次级说明、行内元信息 |
| `--text-sm` | 13 | 18 | agent 名、列表行、区块标题 |
| `--text-base` | 14 | 20 | 正文 |
| `--text-lg` | 16 | 24 | 模态标题 |

**五档封顶**。字重只用 400 / 500 / 600——再多一档就不会有人分得清该用哪个。

> 原第六档 `--text-xl`（20px，给「管理面板页面标题」）**已删除**：主面板改成单页之后
> 没有页面标题了（`functional-design.md §13`），模态标题用 `--text-lg`。
> **一档没人用就不该留着**——字阶的意义就是每一档都有归属。
> （2026-10-23 补：这一档从文档里删掉时，`styles.css` 与 `styles.test.ts` 没有跟着改，
> 于是测试红了一阵。三处一起改了，`--text-xl` 现在不存在。）
>
> **字号与文字分级是两件事**：分级（§2）说「这个字该多重」，字号说「这个字该多大」。
> 一个 12px 的说明句可以是 tertiary，一个 13px 的说明句也可以是 tertiary。

行高与字号成对，令牌名是「字号令牌 + `-leading`」：`--text-sm` 配 `--text-sm-leading`。
字号与行高是同一个决定，拆开写就会有人只改一半。

## 4. 间距与圆角

间距是 **4 的倍数**：`2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32`。
其中两档不是 4 的倍数，是刻度上**仅有的两处例外**：6 用在图标与文字之间——它比 4 松、比 8 紧，
正好是那一处的需要；2 是最小的一档，用在 1px 描边这类贴边的地方（徽标的上下内边距就是它）。
刻度之外没有值：14px、10px 这种「看起来差不多」的间距一律不写，它们是漂移的开始。

圆角：`--radius-sm: 4` / `--radius-md: 6` / `--radius-lg: 10`，徽标用 `999`（胶囊，`--radius-pill`）。
**卡片用 `--radius-lg`（10）**（§5 的两层表面）。

**窗口几何不进间距刻度。** 标题栏高度、行高、面板宽度、托盘留白这些是**窗口的结构尺寸**，
不是「两块内容之间的呼吸」：它们各自有名字（`--titlebar-height: 36px`、`--row-height: 40px`、
`--panel-gutter`、`--panel-width`），不参与上面那条对账。
道理和 6/2 那两档例外一样：**刻度管的是间距，不是所有长度**。

## 5. 骨架一：标题栏（常驻状态）

**标题栏是托盘应用最重要的一块，因为它的职责是「不用进去也知道在不在跑」。**

高度 **36px**（`--titlebar-height`），整条是窗口拖拽区（`data-window-drag` → `-webkit-app-region: drag`），
里面的按钮要显式 `no-drag`，否则点不动。

```
[icon] abx  ›  共享          [docker 沙箱]  ● 3 个 agent 在运行
```

| 位置 | 内容 |
|---|---|
| 左 | 16px 品牌图标 · `abx` · `›` · **当前视图名**（单页就一个名字） |
| 右 | **后端标记**（`docker 沙箱` / `⚠ 未隔离`，见 §10）· **常驻状态**：状态点 + 一句话 |
| 右（有拦截时） | 后端标记左边多一枚 `2 条被拦下`（`--danger`），点开是详情（§9） |

**四条硬规则：**

1. **没有 agent 在跑时显示 `空闲`，不要隐藏。**「什么都没有」本身就是信息；
   藏起来的话，用户看到一片空白，分不清「没在跑」和「界面坏了」。
2. **状态点用形状分档**：运行中 = 实心圆 + `--accent`；空闲 = 空心圈 + `--text-quaternary`。
   与 §7 的状态点同一套语言。
3. **文案里不出现用户不认识的词。** 不写「N 舱」，写 `3 个 agent 在运行`
   （`functional-design.md §0.2`：术语对小白等于没说）。
4. **后端标记常驻**。它是安全事实，不是设置项——不能藏进设置里等人去找。

**`local` 后端要多一条警示条**，就在卡片顶部、第一块内容之前：浅红底 + `--danger`，
写**后果**（「未隔离：agent 能读到你电脑上的任何文件，也能连任何网站」），
不写「非沙箱」。标题栏那枚也换成 `--danger`。**两边一起出现**：标题栏那枚是「一直看得见」，
警示条是「躲不掉」。

**左右留白按平台算**（照 osw 的 `resolveWindowTitlebarInsets`）：macOS 左侧让开 80px 给交通灯；
其它平台右侧让开 160px 给窗口按钮；全屏时两侧都收到 16px。

**标题栏只用窗口底色**（`--bg`），不是卡片色——它是窗口的一部分，不是浮起来的东西。

## 6. 骨架二：两层表面

**窗口底 + 一张浮起的卡片。** 这是「像应用」和「像网页」的分界：

```
窗口（--bg，整幅）
  └─ 留白 p-2（8px）
      └─ 卡片（--surface，border-radius: --radius-lg，极细边框 + 一层浅阴影）
          └─ 卡片内 px-6 py-5（24 / 20）
```

- **边框只有 0.5px 的观感**，配 `0 1px 3px rgb(0 0 0 / .06)` 的浅阴影。
  卡片靠**明度差**（`--bg` → `--surface`）站住，边框只是收边——不靠重阴影和重描边。
- **不许把三块内容直接铺在窗口上。** 那正是 v4 看起来像网页的原因。
- 托盘面板本来就是这套（透明窗口 + 一张卡片），主面板向它看齐——
  **两个面板是同一个东西的两种尺寸**。

## 7. 骨架三：行规格与动作位

列表行（共享列表、设置项、agent 行）统一：

| 项 | 值 |
|---|---|
| 行高 | **40px**（`--row-height`），内容垂直居中 |
| 行间 | **极淡分隔线** `1px --border`，**不用斑马纹** |
| 左 | 图标（quaternary）→ 主名（primary） |
| 中 | 次要信息（secondary）；说明句（tertiary）跟在主名下面 |
| 右 | **动作位**（图标按钮，右对齐）+ 时间戳（quaternary，右对齐） |

**动作位必须常显，不允许「悬停才出现」。** hover 才出现的动作在触屏和键盘下等于不存在。
常显的代价是它一直占着注意力，所以用 `--text-quaternary` 的图标来还这笔账——
**看得见但不在抢戏**。

**每行右端最多两个动作。** 再多就不该是行内动作，应该是「打开所在文件夹」这类批量出口。

## 8. 骨架四：每一块都要有一行说明句

**区块标题下面必须有一行 `--text-tertiary` 的说明**，回答**这是什么 / 会影响什么**。

| ✅ 说后果 | ❌ 同义反复 |
|---|---|
| 「这里的东西所有 agent 都能读，但它们改不了」 | 「这里是管理共享文件的地方」 |
| 「点一下开始；它只看得到你共享的文件」 | 「agent 列表」 |
| 「软件能自己定的都定好了，只有账号要你填」 | 「应用设置」 |

判据一句话：**说明句里必须有不看标题就不知道的信息。** 如果没有，那一行是噪音，删掉。

判的是**内容，不是形式**：托盘面板没有额外加说明句，因为它的两处文案
（`共享给全部 agent` + `拖到这里 → 全部 agent 立刻可见`）本身就是那句说明
——为守规矩再加一行，等于在最小的界面上加一句废话。

## 9. 状态怎么表达

### 用「浅底 + 同色深字」的胶囊

```
运行中   浅绿底 + 深绿字      --accent-soft / --accent-deep（浅色）
已停止   浮起块底 + 三级字    --raised / --text-tertiary
被拦下   浅红底 + 深红字      --danger-soft / --danger
```

**文字永远在，颜色只是加速识别。** 胶囊这一个形式同时满足「不只靠颜色」和「一眼可扫」，
不需要再发明第二、第三通道。

> 这取代了早期那套「形状 + 填充 + 标记 + 文字」四通道设计：那是**过度设计**。
> 浅底同色深字已经够了，而且可扫性更高（osw 的请求日志就是这么做的）。
> **顺带纠正一处**：胶囊的底与字必须**一起实测**——osw 那套 `bg-success/10 + #079455`
> 实测只有 **3.49:1**，不到 AA。照抄形状，不照抄没有量过的数值。

### 与颜色无关的那些状态

| 状态 | 表达 |
|---|---|
| 正在运行 | 实心块 + `--accent` 描边 + 胶囊「运行中」 |
| 可启动 | 描边块（`--border-strong` 虚线：「这里可以动手」）+ 一个**动作词**（托盘里是 tooltip 的「启动」，管理面板里是按钮），**不能看起来像禁用** |
| 未安装 / 未构建 | 中性块 + 一句「为什么」+ 一个动作（「先安装」） |
| 失败 / 被拒 | `--danger` + 图标 + 具体原因，**原因不能省** |

「未安装」与「失败」是两种不同的东西：前者是可预期的、有下一步；后者是出错了。
它们不该长得一样。**两者都不用 `--accent`。**

### 按钮

| 类型 | 样子 |
|---|---|
| 主按钮 | **前景色实心**：`--text-primary` 底 + `--bg` 字（浅色 17.24:1 / 深色 15.68:1） |
| 次按钮 | 透明底 + `--border-strong` 描边 + `--text-primary` 字 |
| 危险动作 | `--danger` 描边 + `--danger` 字；**只有真的会毁东西的地方用** |

## 10. 两个面板的关系

同一个设计体系，两种密度：

- **托盘面板**（422 宽 = 卡片 366 + 左右各 28 留白）：上 icon 横向展开、下共享列表。
  只做两件事——快速打开已装 agent、查看共享内容。
- **管理面板**（独立窗口）：设置与管理。密度更高，用同一套令牌与字号档位。

管理面板里**必须能看出当前用的是哪个后端**（`docker` / `local`）——位置在**标题栏右端**，
和常驻状态并排（§5）。主面板没有 header 了，后端标记不能跟着 header 一起消失。

**宽度算式**（2026-10-23 按 §6 的两层表面重算）：主面板 **820** = 卡片 804 + 左右各 8（`p-2`）；
卡片内 **756** = 804 − 2×24（`px-6`）。

> 旧算式是「820 = 内容 780 + 左右各 20；卡片内 750 = 780 − 2×15」。那套数出自**还没有卡片**
> 的那一版（三块内容直接铺在窗口上，§6 说的正是那一版为什么像网页）。加了卡片之后，
> 780/750 这两个数就没有对应的东西了——留着它，读的人会以为卡片是 780 宽。

**同一个东西在两个面板里要用同一种表达**：「只读」在托盘侧栏曾是胶囊，
主面板是行尾次要文字。**胶囊是给「少数与众不同的行」用的**——每一行都有的东西做成胶囊，
就变成五个重复的色块。**统一用行尾次要文字。**
`local` 不是沙箱，绝不能和 docker 长得一样——这是安全信息，不是外观偏好。

## 11. 怎么保证它没被违反

`~/.openclaw/workspace/skills/design-review-loop/scripts/audit.mjs`（零依赖 CDP 审计）
检查对比度、溢出、触控尺寸、字号与间距。**正文 < 4.5:1 视为失败**。

不写「视觉上可以」，也不因为「osw 就是这么做的」而豁免。
