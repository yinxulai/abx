# 第一个体验版 · 验收清单

**这份清单的作用**：把「体验版」从一句愿望变成一组**能逐条打勾或打叉**的动作。
不含「差不多可以了」这种判据。

## 一、体验版是什么

一个 macOS 托盘应用：点图标出一个面板，把文件拖进去，它起一个隔离舱并在里面跑 agent，
模型走 OSW 管理 —— 全程不把宿主的任何密钥交给舱。

**不是一个**跨平台工具、**不是**命令行程序、**不是**只跑测试的代码库。

## 二、能不能在本机验证

| 项 | 本机（Linux，`DISPLAY` 为空） | macOS |
|---|---|---|
| 单元/集成测试 | ✅ | ✅ |
| 类型检查、lint | ✅ | ✅ |
| 代码构建 | ✅ | ✅ |
| **打包出 `.app`** | ❌ 不可能 | ✅ |
| **点开托盘看到面板** | ❌ 不可能 | ✅ |
| **拖文件起舱** | ❌ 不可能 | ✅ |
| 真 docker 起舱（不涉 GUI） | ✅ | ✅ |

**结论**：本机能验证到「代码正确、测试全绿、能构建」；**盘面上的最后一公里必须在 Mac 上走**。

## 三、本机可打勾的验收项

```
pnpm lint         # ✓ Lint passed（含包边界检查）
pnpm typecheck    # ✓ Type check passed
pnpm test         # ✓ All tests passed
pnpm build        # ✓ 产出构建产物
```

逐条附加：

- [ ] `pnpm lint` 通过，且**包边界检查**报「boundaries respected」
- [ ] `pnpm typecheck` 通过，**没有**任何 `Cannot find module` 或残留 `.ts` 后缀
- [ ] `pnpm test` 全过，且包含这几条**对抗性**断言（缺一条就不算过）：
  - [ ] 一个舱的令牌**在另一个舱上无效**
  - [ ] 伪造 `ctx-abx-cell-id` 头 → 401
  - [ ] 挂载 `~/.claude/.credentials.json` 被**拒绝**
  - [ ] 错误令牌 → 401
- [ ] 生成的 agent 配置里**没有** `model` 字段
- [ ] 生成的 agent 配置里 `baseUrl` 指向**气闸舱面**，不是 OSW
- [ ] 挂载参数里每一项都是**单文件 + 只读**
- [ ] 默认配置里**只有** `osw` 一个上游

## 四、必须在 Mac 上走的验收项

准备：把宿主环境变量 `ANTHROPIC_API_KEY` 之类的真密钥**不要**设进舱；
OSW 跑起来（本地代理端口），abx 的 `osw` 上游指向它。

- [ ] `pnpm dev`（或装好的 `.app`）能起来，**Dock 里没有图标**（托盘应用）
- [ ] 点托盘图标出面板；面板**宽 422、卡片宽 366**，四周留白能看到阴影
- [ ] 点面板外任意处，面板**隐藏**；再点图标**立刻**回来（不重建窗口、不闪）
- [ ] 面板内容变高变矮时，窗口**跟着变**（高度由渲染层量、宿主改尺寸）
- [ ] 明暗跟随系统，**面板里没有切换器**
- [ ] 把一个文件拖到托盘图标上 → 面板里出现它；再拖到面板的拖放区 → 也接住
- [ ] 起舱后：`docker ps` 能看到容器；容器里 `cat ~/.claude/settings.json`
      看到的是**生成的最小配置**（一个 baseUrl + 占位符）
- [ ] 容器里**读不到** `~/.claude/.credentials.json`（文件不存在，不是权限不足）
- [ ] 舱内 agent 发一次请求 → **真的通**（模型由 OSW 提供）
- [ ] 审计文件里能看到这条请求，且**cellId 正确**、**没有密钥值**
- [ ] 关掉 agent → 容器**自动销毁**；`docker ps` 里没有它
- [ ] 舱销毁后，它那个令牌**立刻失效**（拿旧令牌再请求 → 401）

## 五、已知会在 Mac 上第一次踩的坑

按「最可能先遇到」排序：

1. **挂载源不在 Docker Desktop 共享路径内** → `mounts denied`，报错看不懂。
   预置对策：起舱前检查挂载源是否在共享路径内，不在就抛人话错误。
2. **舱面地址不是 `172.17.0.1`** → 在 macOS 上必然连不上。
   预置对策：探测 + `host.docker.internal` + 来源网段校验。
3. **出口白名单太紧** → 舱内 agent「一开就不好用」，因为它还会连别的域名。
   预置对策：默认拒绝是对的，但要把「被拒的域名」**记进审计并显式提示**，
   让用户能一条一条加白名单，而不是猜。
4. **密钥污染** → 舱的环境变量里不该出现真密钥。
   预置对策：已有 `assertNoForbiddenEnv` + 环境脱敏，Mac 上再核一遍。

## 六、体验版**不做**的事（避免范围蔓延）

- 不做 Windows / Linux 桌面版
- 不做命令行
- 不做多舱同时运行的 UI（单个 broker 支持多舱，但面板第一版只呈现一个）
- 不做账号体系、不做云同步
- 不做自动更新
