# abx（气闸）产品规格文档

给 AI coding agent 用的隔离舱，macOS 托盘应用。舱内能像在本机一样干活，
但**拿不到任何真实凭据**、碰不到任务目录以外的文件、删不掉机器。

> **文档状态：能力层与规格已就位，桌面壳未落地。** 核心模块（broker / policy / session /
> mounts）已完成并通过测试；`apps/app`（Electron 托盘）尚未开始。真实状态以
> [`../roadmap.md`](../roadmap.md) 为准。

## 名称与理念

**abx = airlock box。** 名字就是产品：船进出的那道舱门 —— 人和物可以过，
**但气压不会一起走**。凭据就是气压。

这条隐喻决定了下面几条不可让步的取向，它们是本目录所有文档的共同前提：

- **凭据永远在舱外。** 舱内只有占位符，真密钥只存在于宿主的气闸进程内存里。
- **一个地址，没有别的。** 舱内 agent 的配置里**只有一个自定义供应商、只有一个 baseUrl**；
  没有密钥、没有其他供应商、没有账户（见下节）。
- **默认拒绝。** 出口白名单外的域名一律 403 并留痕；文件闸口默认只读、默认不放行。
- **一切可查。** 每次出网、每件出舱的东西都留一条可回溯的记录。
- **可恢复优先。** 移除共享条目只解除挂载，**绝不删原文件**。

## 与 OSW 的关系：这就是要讲的安全

**模型和密钥都配置在 OSW。** OSW 已经在做「把你手上所有渠道收进一个本地地址」这件事
（它的入口就是一个本地地址 + 一个统一模型名）。

所以 abx **不复制任何供应商配置**。舱内 agent 那一侧看到的全部是：

```
一个自定义供应商
  └─ baseUrl:  http://<气闸舱面>/c/<舱令牌>/u/osw
     apiKey:   ***
```

**没有别的东西。** 没有供应商列表、没有模型清单、没有账户、没有第二把密钥。

这就是安全叙事本身：不是「我们帮你把密钥藏好了」，而是
**舱里压根不存在一个可以泄漏的密钥** —— agent 拿到的那个 `apiKey` 是无条件会被
气闸替换掉的占位符，它就算把它打印出来、写进 commit、发给别人，也没有任何用。

因此分工是：

| 谁 | 拿什么 |
|---|---|
| **OSW**（宿主） | 供应商、密钥、模型路由、故障转移 |
| **abx 气闸**（宿主） | 舱令牌校验、出口白名单、凭据替换、审计 |
| **舱内 agent** | **一个 baseUrl，一个占位符。别的什么都没有** |

气闸是**舱的前门**，OSW 是**门后的调度中心**。舱面上只暴露一个地址，
它指向气闸，气闸再把请求交给 OSW。

**不需要修改 OSW。** 它现在提供出去的就是一个**没有鉴权的 baseUrl 服务**，只监听回环地址 ——
而容器只能经 `host.docker.internal` 访问宿主**对外监听**的端口，127.0.0.1 不在其中。
于是气闸成了舱内唯一的出口，OSW 继续只做它自己那件事。

每个 agent 的配置由 abx **生成并以只读方式挂载**，详见
[`overview/agent-config.md`](./overview/agent-config.md)。
| `overview/agent-manifest.md` | Agent 清单：一个 agent 由哪些数据构成（展示 / 持久化目录 / 镜像 / 配置模板） |

> 注：气闸自带的 `upstreams` 配置能力（可直连某家 API）是**开发期与自测用**的。
> 生产形态下，气闸的唯一下游就是 OSW。见 [`overview/architecture.md`](./overview/architecture.md) §14。

## 文档地图

**一个主题只在一处展开。** 下表右列是每个主题的权威文档；其它文档提到同一主题时
只写一句结论加一个链接，不再复述细节。发现两处描述不一致时，以权威文档和代码为准。

「怎么用」写在 [`../source/`](../source/)。

## 核心原则

**默认安全，不靠用户配置。** 一个「默认全开、需要用户手动收紧」的沙箱，
在真实使用里等于没有沙箱 —— 没人会去收紧它。

**一个主题一份文档。** 复述会腐烂，链接不会。
