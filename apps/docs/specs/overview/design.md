## 0. 一句话定位

**abx 不是"更难用的 Docker"，它是一个让 agent 能干真活、同时让用户不用提心吊胆的桌面工具。**

设计上的对手不是"没有沙箱"，而是"用户因为太麻烦所以不用沙箱"。

## 1. 威胁模型（先划界线，否则做出来是花架子）

| 编号 | 风险 | 现实中的样子 | 防线 |
|---|---|---|---|
| T1 | 误删 / 破坏 | 模型执行了 `rm -rf`、覆盖配置、格式化 | 文件只挂任务目录；起舱快照；危险动作审核 |
| T2 | 凭据外泄 | prompt injection 让 agent 读 `~/.ssh`、云凭证、cookie 并外发 | **凭据根本不在舱内**（气闸注入） |
| T3 | 供应链 | `npm install` 的 postinstall 脚本 | 舱内非 root、无 sudo、一次性生命周期 |
| T4 | 数据外泄 | 把代码或密钥发往陌生域名 | 网络默认拒绝，出口按域名白名单 |
| T5 | 持久化逃逸 | 写启动项、cron、shell rc | 舱一次性，退出即销毁 |

T2 是本题指定重点：题目原文"所有主流 MCP 配置时均无需在沙箱内填写任何敏感信息"，
说的就是 T2。

## 2. 设计原则

**P1 · 凭据不进舱。** 不是"进舱后加密"，而是"舱内不存在"。
舱内只有门牌号（指向宿主的地址）和占位符 token。舱被完全攻破，偷到的也只是废纸。

**P2 · 安全等级由方向决定。** 给它的（只读）永远安全；它给你的（新建）永远安全；
改你已有的（覆盖）才需要确认。用户不需要理解机制，只需要记住两条习惯。

**P3 · 宿主终端只是窗口，进程在舱内。** 用户看到熟悉的 Terminal，
执行环境已隔离。这是"不技术化"和"真隔离"同时成立的关键。

**P4 · 像素可以过界，文件系统不行。** 画面流传出去是安全的；
剪贴板、拖拽、截图是三条需要单独设闸的通道。

**P5 · 安全靠可恢复与可审计，而不只靠禁止。** 禁得太多就没人用，
没人用的安全感等于零。默认允许 + 快照 + 审核 + 留痕。

**P6 · 界面上不出现技术词。** 没有 "Docker"、"namespace"、"seccomp"、
"mount"、"policy"。用户看到的是「这个项目 → 在气闸中运行」。

## 4. 五个关键机制

### 4.1 凭据气闸

两个接入入口，共用同一个宿主侧钥匙库：

- **LLM 通道**：Claude Code / Codex 的模型调用。
  机制已验证：`ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` 指向气闸，token 填占位符，
  **不改 agent 一行代码**。
- **通用通道**：MCP server 需要的任意 API 凭据（GitHub token、数据库密码等），
  协议不是 LLM 协议，需要独立的通用凭据入口。

配置里只存环境变量名，永不存明文密钥。

### 4.2 文件三个口

| 口 | 宿主侧 | 舱内权限 | 用途 |
|---|---|---|---|
| **Inbox** | 真实目录 | 只读 | 你要给 agent 看的素材 |
| **Outbox** | 真实目录 | 可写 | agent 的产出，直接落真实磁盘 |
| **Work** | 项目目录 | 可写 + 快照 | 代码，双向往来 |
| **Never** | 不挂载 | 不存在 | `~/.ssh`、`~/.aws`、credentials、`.env`、浏览器 profile、钥匙串 |

代码场景的更强做法：**`git worktree`**。共享 git 对象库（只读），
工作区独立，agent 随便改随便提交，产出天然是一个分支，
宿主侧 `git diff` / `merge` 就是出舱审核。git 本来就是最好的审核机制。

**必须堵的四个坑：**

1. **符号链接逃逸**（安全漏洞）：舱内 `ln -s ~/.ssh/id_rsa ./key` 若被跟随，
   一瞬间绕过全部隔离。必须禁止符号链接指向挂载点之外。
2. **属主与权限**：非 root 写出的文件回到宿主可能打不开。固定 UID 映射或出舱时修正。
3. **路径不一致**：舱内 `/work/src/a.ts` vs 宿主真实路径。
   建议让两者**路径一致**，能省掉大量沟通成本。
4. **大小写敏感差异**：macOS 不敏感 / Linux 敏感，会产生最难查的"宿主能跑、舱内报错"。

### 4.3 网络出口白名单

默认全拒，只放行白名单域名。命中白名单但未配置上游的走直通（仅换凭据）。
越界请求返回 403 并留证。

### 4.4 出舱审核

agent 要写回真实目录中**已存在的文件**、或删除文件时，弹一次确认。
这是把"沙箱"从开发者工具变成**人机协作安全界面**的地方。

### 4.5 审计流水

每次请求一行 JSONL：时间、舱 ID、目标域名、是否放行、状态、耗时。
**不记录 Authorization 的值**，只记是否注入成功。

## 5. 沙箱后端矩阵

| 平台 | 后端 | 状态 |
|---|---|---|
| Linux | Docker | 主实现（需 daemon 运行） |
| Linux | bubblewrap | 备选（需 userns 可用） |
| macOS | App Sandbox / 轻量 VM | 规划 |
| Windows | Windows Sandbox | 规划 |

**本机实测（2026-10）**：`docker` daemon 未启动、`bwrap` 因 userns 被禁
（`setting up uid map: Permission denied`）无法运行。因此**演示环境需要换到 macOS**。

开发期提供 `local` 后端用于跑通逻辑，代码中显式标注
**"不是沙箱，禁止用于演示"**。

## 6. 体验层

**托盘菜单（产品正面）**

```
🟢 气闸运行中 · 1 个舱
─────────────────────────
▸ 在气闸中启动
   Claude Code      ⌘1
   Codex            ⌘2
   dsh              ⌘3
─────────────────────────
🔑 钥匙库：全部在舱外
⚙ 已授权 MCP  2/5
─────────────────────────
审计流水…
复制本地地址 / 打开主窗口
停止代理 / 退出
```

**启动流程**

1. 点「Claude Code」
2. 选项目目录（或从 Finder 右键「在气闸中打开」进来）
3. 起舱：只挂三个口，注入 `BASE_URL` + 占位符 token
4. 打开宿主终端窗口，里面执行的是 `docker exec -it <舱> claude`
5. 托盘图标变色，菜单显示"1 个舱在运行"
6. 关窗口 → 舱回收（默认一次性；长项目可切"工作舱"保留）

**让体验愉快的小设计**

- Outbox 产出即时通知，点一下直接打开
- 拖拽文件到托盘图标 → 自动落进 Inbox 并挂进当前舱

**第一次**：安装 → 托盘常驻 → 在宿主侧填一次真钥匙 → MCP 一键授权

## 8. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | TypeScript + Node 22+ | 团队主栈；与 agent 生态、MCP 生态同构 |
| 编排 / 代理 | Node 内置 `node:http` | 运行期零重依赖，便于审计和阅读 |
| 桌面壳 | Electron | 托盘、多平台、与既有经验一致 |
| 沙箱后端 | Docker（可插拔接口） | 隔离成熟；后端可换 |
| 配置校验 | zod | 配置错误尽早暴露 |
| 审计 | JSONL | 可追加、可 grep、无需数据库 |
| 测试 | vitest | 与既有工程一致 |

**不做**：VM 级方案、跨平台全支持、细粒度策略图形编辑器、企业策略分发。

## 9. 分阶段

**阶段 0 · 核心能力（进行中）**
气闸代理 + 会话编排 + 出口策略 + 命令行。可独立验证。

**阶段 1 · 文件门**
三个口 + 禁区清单 + 符号链接防护 + 路径一致 + 出舱审核。

**阶段 2 · 体验**
托盘 + 面板 + 状态灯 + 产出通知。

**阶段 3 · 演示打磨**
彩排、动效、文案。

**取舍**：必须做——零密钥跑通 agent + 危险动作被拦 + 气闸可拔；
值得做——审计流水、出舱审核、出口白名单；
明确不做——跨平台全支持、GUI 级方案、企业策略。

## 12. 与 OSW 的关系（**这就是要讲的安全**）

**模型和密钥都配置在 OSW。** OSW 已经在做「把你手上所有渠道收进一个本地地址」这件事。

所以 abx **不复制任何供应商配置**。舱内 agent 那一侧看到的全部就是：
**一个自定义供应商、一个 baseUrl** —— 没有密钥、没有供应商列表、没有账户。

**这就是安全叙事本身**：不是「我们帮你把密钥藏好了」，而是
**舱里压根不存在一个可以泄露的密钥**。那个 `apiKey` 是无条件会被替换掉的占位符。

分工：**OSW 是门后的调度中心，气闸是舱的前门。**

| 谁 | 拿什么 |
|---|---|
| OSW（宿主） | 供应商、密钥、模型路由、故障转移 |
| 气闸（宿主） | 舱令牌校验、出口白名单、凭据替换、审计 |
| 舱内 agent | **一个 baseUrl，一个占位符。别的什么都没有** |

### 落地路径

- 气闸的**唯一下游**改为 OSW 的本地地址（生产 `127.0.0.1:9300`）
- 气闸自带的 `upstreams` 直连能力**降级为开发期与自测用**，不再是生产形态
- **不需要改 OSW**：它提供的本来就是无鉴权的回环 baseUrl 服务，容器够不到 127.0.0.1，
  所以气闸天然成为舱内唯一出口（原列的三项「给 OSW 补鉴权/监听面/舱身份」**全部取消**）
- **额外收益**：OSW 的故障转移在沙箱叙事里变成「舱内 agent 完全无感的多渠道韧性」

> 接线细节与配置挂载的三个坑见 [`agent-config.md`](./agent-config.md)。

本阶段保持独立应用，不引入 OSW 的运行时依赖（只对齐技术选型与目录结构）。

## 13. 终局形态（写进文档，不实现）

**FUSE 文件闸口**：舱内挂虚拟文件系统，每一次 open / write / unlink
都经过宿主策略进程，做到"读随意、写要批准、全量审计"，
不需要预先给目录分类。复杂度高，作为架构图上的未来项。
