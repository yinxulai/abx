# 品牌资源

所有位图（打包 png / ico、托盘、文档导出）都由 **一个矢量源** 派生，不要手改 png。

```powershell
pnpm icons
```

脚本：`scripts/generate-icons.mjs`（只用机器上已有的 `google-chrome --headless` 与 ImageMagick `convert`，不依赖 `sharp`）。

## 标志

**一个 Bot 的头。头就是舱体，两只眼睛是那个受控的进出口。**

形状只有一笔：一个圆角矩形，两只眼睛是**挖空**的（alpha 洞），不是画上去的白点。
「洞」不是画法上的讲究，是产品本身——舱是封住的，只有这两个口子通着外面，
而它们通向的是宿主，不是网络。

四条硬约束：

- **16px 下还得像一个东西。** 托盘图标只有 256 个像素，任何细线、镂空、多笔画都会糊成噪点。
  一块圆角实心 + 两只洞是这个尺寸下唯一还完整的构图——缩到 16px，眼睛仍然读得出来。
- **颜色取 osw 那道闪电的前三段。** `#FFE066 → #FF9500 → #F0297C`，来自 osw 的
  `#FFE066 → #FF9500 → #F0297C → #7C3AED`（左上 → 右下）。
  **去掉末端的紫**：紫在 osw 那道细长闪电上只落在最尖端、几乎看不见，
  铺到 abx 这种大色块上就是右下角一块脏。两端对齐意味着两个产品的图标摆在一起是同一套色。
- **眼睛必须是洞，不能是白点。** 洞在深色底板、单色档、纯白蒙版里都成立：透出来的是底色。
  这也是生成脚本里最容易写错的一处——做单色档时要替换渐变的颜色引用，
  而 `mask="url(#abx-eyes)"` 的写法和渐变引用一模一样，一起换掉眼睛就没了（见「防漂移」）。
- **能当纯白蒙版用。** 整套几何不依赖颜色——托盘模板图就是把同一张形状涂成纯白、只留 alpha
  （macOS 的模板图由系统着色，RGB 根本不参与）。

> **标志的渐变不是界面的点缀色。** `packages/console` 的 `--accent` 仍是青绿，
> 标志是暖色渐变，两者各自独立：标志的颜色属于**品牌**，点缀色属于**状态**。
> 为什么不跟着走、osw 那边怎么做的，写在
> [`design-system.md`](../../specs/product/design-system.md) §2 末尾
> 「标志与界面点缀色是两个东西」——这里不重复第二遍。

## 导出方式

**不需要扫墨迹框。** 与 osw 的同名脚本不同，abx 的标志**自带留白**，而且左右与上下各自
对称：头画在 x `16…240`、y `34…222`，**没有描边**，所以 256 的画布上左右各留 16（6.25%）、
上下各留 34（13.3%）。墨迹框就是那个矩形本身，各尺寸直接等比缩放即可，
没有那套「先量墨迹、再 contain-fit」的步骤。
唯一的例外是开发版（右下角要腾出圆点的位置），那里才从已渲染的 1024 里量一次墨迹
（`measureInk`），而不是把 `16` / `34` 写死成常量——标志一改形状，写死的框就会把缝吃掉。

小尺寸靠**超采样**保住边缘：≤ 64px 按 8× 渲染再 `Lanczos` 降采样，≤ 512px 给 4×，
≥ 1024px 给 2×；且**渲染边长不低于 256**（Chrome 在小于约 140px 的窗口下会给出内容坏掉的
截图——尺寸对、内容被压扁，看不见的那种坏）。ICO 的每一帧都按自己的目标尺寸重新光栅化，
不是把 1024 缩下去。

## 产物与用途

### `apps/app/build/`（打包 / 运行时，被 Electron 直接引用）

| 文件 | 尺寸 | 引用它的地方 |
| --- | --- | --- |
| `icon.png` | 1024² 彩色 | 顶层 `icon`、`linux.icon`、`files`、`main.ts` 的 Linux 托盘 |
| `icon-mac.png` | 1024² 彩色 | `mac.icon` |
| `icon-win.ico` | 7 档 16/20/24/32/48/64/256 | `win.icon`、`files`、`main.ts` 的 win32 分支 |
| `trayTemplate.png` | 16² 纯白 + alpha | `files`、`main.ts` 的 darwin 分支（打包版） |
| `trayTemplate@2x.png` | 32² 同上 | `files`；`createFromPath` 会自动认这个 `@2x` 兄弟 |
| `trayTemplate-dev.png` / `@2x` | 同上 | 开发版：标志右下角多一颗圆点，`app.isPackaged` 为假时用 |

**Windows 那张为什么是 `.ico`。** 托盘是唯一「必定被系统按屏幕 DPI 重新取样」的地方，
而 Windows 那条路不接受多倍率：Electron 在 Windows 上走
`NativeImage::GetHICON(GetSystemMetrics(SM_CXSMICON))`，而**非 `.ico` 来源**的 `GetHICON`
会丢弃 size 参数、只取 1× 那一档（`AsBitmap()`）。挂上去的 2× 永远读不到，系统只会拿
16² 放大到 24/32px，于是糊；换 `.ico` 之后每个 DPI 档都有真像素可用。
20 是 125% 缩放那一档（最容易被漏掉，漏了就由 16 拉伸上来）。

> 运行时**禁止**再调用 `image.resize()`：它只会把某一个倍率重新取样一次，正好是要避免的糊。

### 开发版托盘标记

开发版与正式版同时驻留菜单栏时，两枚图标长得一模一样，分不清屏幕上那个是哪个。
所以开发版那张在**标志右下角多一颗独立圆点**：标志缩进左上角，圆点落在右下角，
两者之间留一条约 1.5px（16px 下）的缝——缝没了，圆点就长在标志上，一颗点变成一块鼓包。
`main.ts` 的 `trayTemplate()` 按 `app.isPackaged` 在两个文件名之间挑（与 osw 同构）。

> 这两张都是模板图，所以**必须显式 `setTemplateImage(true)`**，不能只靠文件名：
> Electron 那套启发式认的是「文件名以 `Template` 结尾」，`trayTemplate-dev.png` 正好
> 不满足——不显式声明的话，系统会把这张纯白图当彩色图画出来，压在浅色菜单栏上就是隐形的。

**只有 macOS 有开发版产物。** Windows 走 `icon-win.ico`、Linux 用彩色 `icon.png`，
两边都还没有对应的开发版（要做得再各出一份 ico / png，现在没有这个需求）。

## 防漂移

`packages/console/source/brand-assets.test.ts` 逐字节读这些产物（自带一个只认 8 位 RGBA、
非隔行的 PNG 解码器），校验：文件存在且尺寸精确、`icon-win.ico` 真的含 7 档且每帧 IHDR 对得上、
托盘蒙版的每个不透明像素都是纯白、开发版是真的两块（标志 + 右下角的点）且与正式版不同字节、
所有派生图共用同一个轮廓、单色档与深色底板没有混色、**眼睛在两个单色档里仍然是 alpha 洞**。

再往后一层是**指纹**：`packages/console/source/brand-assets.hash.json` 里存着每个产物的
sha256，逐条与文件对账。上面那些断言看的都是「画得对不对」，指纹看的是
「这张图是不是生成器产出的那一张」——**几何全对、颜色也对，但内容被人涂改过的 png**，
只有它能抓住。清单由 `pnpm icons` 每次重写（它本身就是本次运行的产物），
所以**更新路径就是重跑那条命令**，不需要手编清单：改了真源 → `pnpm icons` → 清单里出现 diff。

改了标志就改真源、跑 `pnpm icons`、再跑 `pnpm test`——三件事都做完才算改完。
